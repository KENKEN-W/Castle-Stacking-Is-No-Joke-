# 五段重ね将軍

数字を読み、同じ城をそろえ、五段を築く、1人用の思考型パズルです。2026年9月23日・第3改訂のルールとデザインを、既存ゲームに2026年9月25日に反映しました。

## 起動方法

このフォルダーの **index.htmlをダブルクリック**して、ChromeまたはEdgeで開きます。インストール、npm、ビルド、ユーザー登録、APIキーは不要です。index.htmlだけを移動せず、**css・js・assets**フォルダーも一緒に置いてください。

端末内保存はブラウザの設定に依存します。保存できない場合も、その場でのプレイは続けられます。外部APIや外部素材への通信はありません。

Node.jsがある場合だけ、任意の確認方法として `node tests/serve.cjs` を実行し、[ローカルのゲーム](http://127.0.0.1:4173/prototype/)を開けます。終了はターミナルでCtrl+Cです。ゲームの利用やGitHub Pagesへの公開に、このサーバーは必要ありません。

## 遊び方と今回の変更

- 空列にはどの数字でも置けます。城がある列には最上段より大きい数字だけ。5列・各5段までです。
- クリック、タップ、数字キー1～5で列を選びます。TabとEnter／Spaceも使えます。
- 各盤面の最初の5手には21～25が出ません。1～25は各1回出現し、先の城は見えません。
- 城は「イスラムの城・西洋の城・日本の城」の3種類。数字とは独立して、各1/3で出現します。種類名も表示するので、色だけで判断する必要はありません。
- 下から4城が同じ種類なら、列ごとに1回＋5点。5城目が別種でも保持し、この加点には倍率をかけません。
- 14城以下で詰まると、その盤面は0点で戦終了。4段の仮加点も失いますが、過去の勝ち戦による累積は残ります。
- 15～24城・同種5段なしで詰まると、得点を加算して自動で戦終了します。再合戦はありません。
- 25城完成、または15城以上・同種5段ありで配置不能になったときは「勝ち戦」。加点して「ボーナスステージ」として同じ戦を続けます。金茶の特別配色と文字表示が、その戦の終了まで続きます。同種5段ができても、まだ置ける間は続けます。
- 15城以上の得点は **城数 × 同種5段の倍率 ＋ 同種4段の加点**。例：18城・5段1列・4段達成1列なら41点です。
- 配置不能時は「置けなかった城」の数字と種類を表示します。
- 戦終了が3回でゲーム終了。3戦合計と、足軽～天下統一大将軍の「あなたの評価」を表示します。

画面の高さに合わせて5列と現在の城を1画面にまとめ、低い横画面では左右に配置します。遊び方・内訳・記録は「前へ／次へ／戻る」のページ式です。詳細の最後からタイトルへ戻れます。

詳しくはゲーム内の「遊び方」を参照してください。[仕様書](docs/spec-v1.md)・[RULES.md](RULES.md)の進行と得点、[DESIGN.md](DESIGN.md)の配色と画面構成に従っています。資料作成時の「未実装」という記載は当時の作業範囲であり、現在の検証状況は[テスト結果](docs/test-results.md)にまとめています。

## 自動保存と旧データ

同じ端末・ブラウザ・サイトで「つづきから」を選ぶと、盤面・現在の城・残りの順番・種類・得点・結果・ボーナス状態を復元します。勝ち戦や結果の再読込でも二重加点しません。

**今回、保存形式とルールのバージョンを3に更新しました。バージョン2以前の保存は再開できません。旧選択状態を勝手に確定したり得点を換算したりせず、新規開始をご案内します。** 旧データを見つけた場合は案内を表示します。読み込んだだけでは削除・再計算せず、「はじめる」で新規ゲームを開始したときに置き換えます。

新形式の保存は1枠です。進行中に「最初から遊ぶ」を選ぶと確認画面が出ます。別端末への同期や複数タブでの同時プレイには対応していません。ブラウザのデータ削除で保存は失われます。直接ファイルを開いた場合と、HTTPや公開サイトを開いた場合の保存は別扱いです。

## ファイルと設定

| ファイル | 役割 |
| --- | --- |
| index.html | ゲームの入口 |
| css/style.css | 墨紺×金の画面、画像カード、画面幅対応、演出 |
| js/config.js | ルール・種類・画像パス・評価・保存バージョンの設定 |
| js/game.js | 数字生成、配置判定、加点、戦の状態遷移 |
| js/storage.js | 自動保存、旧形式の判別、データの整合性検証 |
| js/ui.js | 画面表示、入力、遊び方、結果、読み上げ通知 |
| assets/castles/*.png | 提供された3種類の城画像を英数字名でコピーした素材 |
| tests/game.test.js / tests/index.html | ロジックと保存の自動テスト・ブラウザ用入口 |
| tests/ui.test.js / tests/ui.html | テスト用盤面による画面・操作・保存復帰の検証 |
| tests/balance.js | 固定乱数での10,000盤面比較と3戦ゲームの評価分布 |
| tests/browser.cjs | 開発者向けのEdge・Chrome操作検証、画面記録 |
| tests/serve.cjs | 任意のローカル検証サーバー |
| docs/test-results.md | 結果、確認環境、未確認事項。旧検証記録も保存 |
| docs/test-data.json / docs/browser-test-data.json | 検証の数値・自動テスト出力 |
| docs/screenshots/ | 表示確認で保存した画面 |
| .nojekyll | GitHub Pagesで静的ファイルをそのまま配信するための指定 |

後から調整する値は **js/config.js** に集約しています。

- `CASTLE_COLORS`：既存コードの名前を維持した城の種類設定。`id`、正式名、短い名称、画像、補助色、抽選の重みを設定します。城データの `color` も種類IDを表し、画像の色を解析して判定する仕組みではありません。
- `OPENING_RESTRICTED_TURNS` / `OPENING_MAX_NUMBER`：序盤の出現制限。
- `FOUR_STACK_HEIGHT` / `FOUR_STACK_BONUS`：4段達成と＋5点。
- `MONOCHROME_MULTIPLIERS`：同種5段の倍率。
- `PLAYER_RATINGS`：合計点の下限と評価名。
- `MIN_SCORE_CASTLES`、`NUMBER_OF_COLUMNS`、`MAX_STACK_HEIGHT`、`NUMBER_OF_BATTLES`：得点条件、盤面、戦数。

画面の共通配色はcss/style.css先頭、案内文はjs/ui.jsです。設定を変更したら、案内文・画面幅・倍率表・テストも確認してください。保存には設定の識別情報が含まれ、異なる設定の保存を黙って読み替えません。

## テストの実行

`tests/index.html`をブラウザで開くとロジックテストが走ります。比較ボタンでは独立した10,000盤面と、3戦ゲーム各10,000回をシミュレーションします。比較には時間がかかる場合があります。

Node.jsがある場合は、追加パッケージなしで次も実行できます。

```text
node tests/game.test.js
node tests/balance.js
```

画面テストはサーバー起動後に[画面テスト](http://127.0.0.1:4173/prototype/tests/ui.html)を開きます。テストは一時的に保存枠を使用し、終了時に元のデータを復元します。テスト中は同じサイトのゲームを操作せず、終了までテスト画面を閉じないでください。

`tests/browser.cjs`だけは、開発者向けの任意の検証です。Playwrightが利用でき、Edge・Chromeがインストールされた環境で実行します。必要なら環境変数`PLAYWRIGHT_MODULE`にPlaywrightの配置場所を指定します。ゲーム自体にはこのツールもnpmも不要です。

## GitHub Pagesへ反映する前に

**今回、コミット・Push・公開サイトの更新は行っていません。** まずローカルのindex.htmlで次を確認してください。

1. 3種類の画像・数字・種類名が見やすいこと。スマートフォンでも盤面と現在の城を確認できること。
2. 自動戦終了、4段の仮加点、勝ち戦後のボーナス表示が意図に合っていること。
3. 旧保存を引き継げず、新規ゲームになる変更を受け入れられること。
4. 提供画像を公開用素材として使用してよいこと。

公開を依頼する際は、index.htmlとcss・js・assetsを同じ構成でアップロードします。公開元はルートのindex.htmlです。既存のPages設定を維持し、反映後に公開URLで画像・保存・操作を確認してください。GitHub上での操作は、明示的な依頼を受けてから行います。

基準サイズは320×568、320×740、375×667、375×812、1280×720、740×320（ブラウザの表示領域）です。

詳しい検証結果と実機での未確認事項は[テスト結果](docs/test-results.md)に記載しています。
